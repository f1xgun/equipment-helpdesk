# Equipment Helpdesk

API для учёта неисправностей оборудования компьютерного класса. Позволяет
зарегистрировать заявку, найти её по номеру, отфильтровать список и записать
результат ремонта. Данные хранятся в SQLite.

## Установка и запуск

Проект проверен на Python 3.12; эта же версия используется в CI.
Команды ниже — для macOS/Linux.

```bash
git clone https://github.com/f1xgun/equipment-helpdesk.git
cd equipment-helpdesk
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Это обычный запуск без автоматической перезагрузки. Для разработки можно
добавить `--reload`. Остановка — `Ctrl+C`.

Документация и отправка запросов через браузер: <http://127.0.0.1:8000/docs>.
Отдельного веб-интерфейса нет.

Для запуска без инструментов тестирования достаточно установить
`requirements.txt` вместо `requirements-dev.txt`.

### Через make

Если установлен `make`, активация окружения не нужна:

| Команда | Действие |
| --- | --- |
| `make install` | Создать `.venv`, установить зависимости и создать `.env`, если его нет |
| `make run` | Запустить без перезагрузки |
| `make dev` | Запустить с `--reload` |
| `make test` | Выполнить тесты |
| `make check` | Проверить `/health` и `/version` уже запущенного сервера |

Для создания окружения по умолчанию используется `python3.12`; другой
интерпретатор можно указать через `make install PYTHON=/путь/к/python`.
Для другого порта: `make run PORT=8001` и `make check PORT=8001`.

## Настройки и БД

В `.env.example` приведена единственная настройка:

```dotenv
DATABASE_URL=sqlite:///./helpdesk.db
```

Приложение читает `.env` из корня проекта. Переменная окружения имеет приоритет
над файлом. Если настройка не задана, используется значение из примера.

Запуск с другой БД без изменения `.env`:

```bash
DATABASE_URL=sqlite:///./demo.db python -m uvicorn app_final:app
```

Относительный путь к SQLite отсчитывается от каталога запуска. Файл и таблица
создаются при первом запуске; данные сохраняются после остановки приложения.
Настоящий `.env` и файлы БД исключены из Git.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка соединения с БД |
| `GET` | `/version` | Версия приложения |
| `POST` | `/tickets` | Создание заявки |
| `GET` | `/tickets/{ticket_id}` | Заявка по номеру |
| `GET` | `/tickets` | Список; фильтры `status` и `room` |
| `PATCH` | `/tickets/{ticket_id}/status` | Изменение статуса |

Приоритеты: `low`, `normal`, `high`. По умолчанию — `normal`.
Новая заявка получает статус `open`. Разрешены только переходы
`open → in_progress → closed`. Для закрытия нужен непустой `resolution`;
время закрытия заполняется автоматически. Повторное открытие не поддерживается.

Фильтры можно комбинировать: `/tickets?status=open&room=305`.
Условия объединяются через AND, результат упорядочен по `id`.
Если совпадений нет, возвращается пустой список.

Пример создания и закрытия заявки (вместо `1` подставить полученный `id`):

```bash
curl -X POST http://127.0.0.1:8000/tickets \
  -H 'Content-Type: application/json' \
  -d '{"device_code":"PC-014","room":"305","description":"Монитор не включается"}'

curl -X PATCH http://127.0.0.1:8000/tickets/1/status \
  -H 'Content-Type: application/json' \
  -d '{"status":"in_progress"}'

curl -X PATCH http://127.0.0.1:8000/tickets/1/status \
  -H 'Content-Type: application/json' \
  -d '{"status":"closed","resolution":"Заменён кабель питания"}'
```

Успешное создание возвращает `201`. Отсутствующая заявка — `404`,
недопустимый переход статуса — `409`, некорректные входные данные — `422`.

## Тесты и CI

```bash
python -m pytest -v
```

Тесты используют временные SQLite-файлы, не рабочую БД.
GitHub Actions запускает их при `push` и `pull_request`. После успешной проверки
создаётся artifact `equipment-helpdesk` с исходниками приложения и
`requirements.txt`. Запуски и архивы доступны во вкладке
[Actions](https://github.com/f1xgun/equipment-helpdesk/actions).

## Проверка и диагностика

При запущенном сервере:

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/version
```

Оба маршрута должны вернуть `200`. `/health` отвечает `{"status":"ok"}`,
`/version` — JSON с полем `version`. При недоступности БД `/health` возвращает `503`.

Логи выводятся в терминал с Uvicorn: запуск и остановка приложения, ID созданных
заявок, смена статусов и ошибки проверки БД. Описания неисправностей, результаты
ремонта и строка подключения в прикладные логи не попадают.

| Проблема | Что проверить |
| --- | --- |
| `ModuleNotFoundError` | Активировано ли `.venv`, установлены ли зависимости |
| `Address already in use` | Выбрать другой порт: `--port 8001` |
| `unable to open database file` | Путь к БД, наличие родительского каталога и права записи |
| `/health` вернул `503` | Сообщение `Database health check failed` в терминале, путь и доступность БД |
| API вернул `422` | Поле `detail` в ответе и схема запроса в `/docs` |

Если БД недоступна уже при старте, приложение не запустится; причина будет
в терминале.
